# Rule: DataSpider Setting Sheet (DataSpider設定 / DataSpider Setting)

## Sheet name keywords

`DataSpider設定`, `DataSpider`, `DataSpider Setting`, `Cấu hình DataSpider`

## Note

The sheet defines the DataSpider configuration used to export data from SAP: export parameters, APIs, data mapping, and processing rules.

## Goal

Output: metadata + 4 config table groups, all keeping dynamic columns. This is configuration data — **do NOT interpret, do NOT transform content, only normalize to Markdown**.

## Heading hierarchy

- YAML frontmatter (metadata — see section 1) at the very top of the file, before the H1
- Sheet name = `#` (H1)
- Each group (Export Parameters / API Configuration / Export Field Mapping / Processing Rules) = `##` (H2)

## 1. Metadata — YAML frontmatter (machine-readable, for downstream chunking/retrieval)

Emit metadata as YAML frontmatter, not a bullet list, so a chunker can attach the same metadata to every chunk produced from the file.

**All 12 keys below are the standard schema shared by every sheet rule in this skill — every generated `.md` file has the SAME key set, in the SAME order, regardless of sheet type.** Keys that don't apply to this sheet (`class_name`, `current_version`, `file_name`) are still present, with an empty string value. This makes every file's frontmatter schema identical, so a downstream chunker/vector-DB never needs to check whether a key exists.

```yaml
---
document_type: ""
project_name: ""
business_name: ""
function_id: ""
function_name: ""
created_date: 2025-04-24
last_updated_date: 2025-04-24
last_updated_by: ""
sheet_name: ""
class_name: ""
current_version: ""
file_name: ""
---
```

Field mapping (source label → YAML key):

1. Document Type (種類) → `document_type` — MUST be exactly one of two fixed values: `概要設計書` (Basic Design) or `システム要件定義書` (Detailed Design). Determine it from the workbook's Cover sheet / file name; if genuinely undeterminable, leave `""` — do NOT invent a third value.
2. Project Name (プロジェクト名) → `project_name`
3. Business Name (業務名) → `business_name`
4. Function ID (機能番号) → `function_id` (keep as a string)
5. Function Name (機能名称) → `function_name`
6. Created Date (作成日) → `created_date` (convert to ISO `YYYY-MM-DD`)
7. Last Updated Date (最終変更日) → `last_updated_date` (same ISO conversion)
8. Last Updated By (最終変更者) → `last_updated_by`
9. `sheet_name` → the raw Excel sheet name, not translated
10. `class_name` → not applicable to this sheet; always `""`.
11. `current_version` → not applicable to this sheet; always `""`.
12. `file_name` → not applicable to this sheet; always `""`.

If a field is empty in Excel, keep the YAML key with an empty string value (`""`). Do NOT omit the key and do NOT fabricate a value.

## 2. Export Parameters — Markdown Table (dynamic columns)

Keep all columns. Commonly seen: SAP Parameter | Value | Description | Source | DataSpider | Note.
Includes parameters such as: Job ID, Script Name, File Directory, Process Type, File Name, API Sequence (`<start>` → `<end>`), Printer, Output Printer, Form Name, Output Spool Mode, Document Name, User Name, Environment Name.

## 3. API Configuration — Markdown Table (dynamic columns)

Keep all columns. Commonly seen: API | Value | Description | Source | DataSpider | Note.
Preserve the order of the APIs and their config values.

## 4. Export Field Mapping — Markdown Table (dynamic columns)

Keep all columns. Commonly seen: Field ID | SAP Field | Description | Source | DataSpider | Note.
**Keep the entire FIELDxxx list — do NOT merge, do NOT drop any row.**

## 5. Processing Rules — Markdown Table (dynamic columns)

Keep all columns. Commonly seen: Item | Rule / Description | Source | Note.
Includes rules such as: Constant Value, value taken from API, value generated by SVF, Printer selection rule, Form selection rule, File Name generation rule, Output Mode rule.

## Conversion Rules (MANDATORY)

- Preserve the order of the rows.
- Do NOT drop any FIELDxxx or API.
- Do NOT merge consecutive FIELDxxx rows.
- Preserve JSON, API, Script, and config values verbatim.
- If a cell is merged in Excel → write it once in the corresponding section.
- Convert all tabular data to Markdown tables, preserving structure and column names.
- Do NOT change any Parameter name, Field ID, API, or config value.
- Do NOT transform or interpret content; only normalize to Markdown.
- If a metadata field is empty, keep the line with an empty value. Do NOT fabricate.
